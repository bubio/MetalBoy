# Feature Specification: CLI 起動型 GAME BOY エミュレーター

**Feature Branch**: `001-gb-cli-emulator`

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "GAME BOYエミュレーターの開発です。エミュ表示以外にGUIを持たず、CLIから起動、オプション設定します。オプションの永続化もありません。BIOSは必要としません。オプション設定は画面スケール x1 - x8 (default x3)、音量(default 50%)とします。キー割り当ては、矢印=十字キー、Z=B、X=A、Enter=Start、スペース=Select とします"

## Clarifications

### Session 2026-10-18

- Q: 動作対象とする Game Boy ハードウェアの範囲はどこまでか → A: DMG（初代
  Game Boy）のみ。Game Boy Color（CGB）とその拡張機能は対応範囲外とする
- Q: カートリッジのセーブデータ（電池保存領域）を終了後にファイルとして
  保存して次回起動時に復元するか → A: 保存して復元する（ROM と同じ場所に
  対応するセーブファイルを作成し、次回起動時に復元する）
- Q: ポーズ（一時停止）機能とそのキー操作を設けるか → A: 設けない。
  エミュ表示以外のランタイム操作は終了操作のみとする
- Q: 対応するカートリッジマッパー（ROM のバンク切替方式）の範囲はどこまで
  か → A: MBC0（マッパーなし）・MBC1・MBC2・MBC3・MBC5 に対応する
- Q: エミュレーションが正しく動いていると判定する受け入れ基準は何か →
  A: 公開されているハードウェア挙動テスト ROM（blargg 系の CPU 命令・
  タイミング検証 ROM 等）に合格することを基準とする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ROM を指定して起動しゲームを遊ぶ (Priority: P1)

ユーザーはコマンドラインから ROM ファイルを起動引数に指定してエミュレーターを
起動し、ゲーム画面と音声が出力され、Game Boy のボタンを固定のキー割り当てで
キーボードから操作してゲームを遊ぶことができる。

**Why this priority**: エミュレーターの中核的価値（ROM を遊べること）であり、
これなしに他の価値は存在しない。MVP の本体。

**Independent Test**: ROM ファイルパスを起動引数として実行し、画面表示・キー
入力の反映・音声出力をそれぞれ個別に確認できる。ここが成立しなければ他の
ストーリーは意味を持たない。

**Acceptance Scenarios**:

1. **Given** 有効な Game Boy ROM ファイルが存在する、**When** CLI に当該
   ファイルパスを渡して起動する、**Then** エミュレーションが開始され、
   ゲーム画面が専用の表示ウィンドウに出力される
2. **Given** エミュレーターが動作中である、**When** キー割り当て通りに入力
   する（矢印 / Z / X / Enter / スペース）、**Then** それぞれ十字キー / B /
   A / Start / Select としてゲームに反映される
3. **Given** エミュレーターが動作中である、**When** ゲーム内で音が鳴る場面に
   到達する、**Then** 設定された音量に応じた大きさで音が出力される

---

### User Story 2 - 起動引数でオプションを指定する (Priority: P2)

ユーザーは CLI のオプション指定によって、画面スケールと音量を変更して起動
できる。オプションを指定しなかった場合は既定値（スケール x3、音量 50%）で
起動する。設定は永続化されず、毎回の起動引数でのみ有効である。

**Why this priority**: 利便性・環境適応の要素であり、本体（US1）が成立した後
に価値が生まれる。起動時の初期化処理だけで独立して提供・検証できる。

**Independent Test**: 同一 ROM を複数のオプション組合せで起動し、表示サイズ
と音の大きさの差異をそれぞれ確認できる。

**Acceptance Scenarios**:

1. **Given** 有効な ROM が存在する、**When** 画面スケールを指定せずに起動
   する、**Then** 画面スケールは x3 で表示される
2. **Given** 有効な ROM が存在する、**When** 画面スケールを x1〜x8 の
   いずれかで指定して起動する、**Then** 指定した倍率に応じた大きさで画面が
   表示される
3. **Given** 有効な ROM が存在する、**When** 音量を指定せずに起動する、
   **Then** 音量 50% で音が出力される
4. **Given** 有効な ROM が存在する、**When** 音量を 0〜100% のいずれかで
   指定して起動する、**Then** 指定した音量で音が出力される
5. **Given** 範囲外の値（例: スケール x0 / x9、音量 150%）を指定した、
   **When** 起動する、**Then** 起動は失敗し、許容範囲を示すエラー
   メッセージが標準エラー出力に表示される（既定値へは静かにフォール
   バックしない）

---

### User Story 3 - クリーンな終了と明確なエラー (Priority: P3)

ユーザーは実行を任意のタイミングで終了でき、誤った入力（存在しない ROM、
無効な ROM、範囲外オプション、ROM 未指定）では原因を説明するエラーで即座に
失敗する。

**Why this priority**: 品質・操作性の保証であり、本体（US1）と操作性
（US2）が成立した後で価値が確定する。

**Independent Test**: 正常入力と異常入力それぞれで起動を試み、終了挙動・
エラーメッセージ・失敗の速さを確認できる。

**Acceptance Scenarios**:

1. **Given** エミュレーターが動作中である、**When** ユーザーが終了操作を
   行う、**Then** クリーンに終了し、後片付けが残らない
2. **Given** セーブ対応カートリッジの ROM でゲーム内のセーブを完了した、
   **When** ユーザーが終了操作を行い、同じ ROM で再度起動する、**Then**
   前回セーブしたゲームの進行状態が復元される
3. **Given** 存在しないファイルパスを ROM として指定した、**When** 起動
   する、**Then** 存在しないことを示すメッセージが標準エラー出力に出力され
   起動に失敗する
4. **Given** ROM として不適なファイルを指定した、**When** 起動する、
   **Then** 無効な ROM であることを示すメッセージが標準エラー出力に出力され
   起動に失敗する
5. **Given** オプションが範囲外である、**When** 起動する、**Then** 1 秒
   以内に許容範囲を示すエラーで失敗する（起動後のゲーム画面が表示されない）

### Edge Cases

- 引数に ROM ファイルを指定しなかった場合: 使い方を示すメッセージを標準
  エラー出力に表示して失敗する
- オプション値が範囲外の場合（スケール x1〜x8 以外、音量 0〜100% 以外）:
  許容範囲を示して失敗する（既定値への沈黙フォールバックはしない）
- 音量 0% が指定された場合: 音声出力なしで正常に動作する
- GUI 表示が利用できない環境で起動された場合: 起動に失敗し、その旨の
  メッセージを表示する
- 本エミュレーターが対応範囲外のカートリッジが指定された場合: 対応して
  いないことを示すメッセージを表示して失敗する
- CGB 専用 ROM が指定された場合: DMG 非対応であることを示すメッセージを
  表示して失敗する
- 非対応マッパー（MBC0/1/2/3/5 以外）の ROM が指定された場合: 非対応の
  マッパーであることを示すメッセージを表示して失敗する
- ゲーム進行中に終了した場合: 設定は保存されない（オプション永続化なしの
  仕様に整合）。セーブデータのみ FR-013 に従ってファイルに保存される
- セーブ対象のディレクトリが書き込み不可である場合: ゲーム自体は動作を
  続けつつ、セーブデータが保存できなかった旨を分かる形で通知する
- セーブファイルが破損している場合: それを無視して空のセーブ領域で起動
  するか、エラーで失敗するかは計画フェーズで確定する（少なくとも黙って
  上書きはしない）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: エミュレーターは、CLI からの起動時に ROM ファイルパスを
  引数として受け取り MUST エミュレーションを開始する
- **FR-002**: エミュレーターはゲーム画面を専用の表示ウィンドウに出力する
  が MUST 存在する。エミュ表示以外の GUI 要素（メニュー、設定画面、
  ダイアログ等）は MUST NOT 存在する。すべての設定は CLI 起動引数で
  行う
- **FR-003**: ユーザーは起動引数で画面スケールを x1〜x8 の範囲で指定でき
  が MUST 存在する。既定値は x3。指定がない場合、画面は x3 の大きさで
  表示される
- **FR-004**: ユーザーは起動引数で音量を 0〜100% の範囲で指定できるが
  MUST 存在する。既定値は 50%
- **FR-005**: 範囲外のオプション値が指定された場合、エミュレーターは許容
  範囲を示すエラーメッセージを標準エラー出力に出力して MUST 起動に
  失敗する。既定値への沈黙フォールバックは MUST NOT 行う
- **FR-006**: オプションの永続化（設定ファイル・環境変数等への保存）は
  MUST NOT 行う。設定の有効範囲はプロセス 1 回の寿命に限る
- **FR-007**: エミュレーターは BIOS を必要とせず MUST エミュレーションを
  開始できる。BIOS を読み込む手段・BIOS 実行の挙動再現は提供して
  MUST NOT 存在する（起動時の必須初期化のみを行う）
  - 例外: 開発用検証ツール（`metalboy-mooneye --bios`）に限り、ハードウェア
    検証（Mooneye boot 系テスト）のために実 BIOS を供給できる。この経路は
    エミュレーションコア（`MBGameBoy.bootROMData`）と当該ツールにのみ存在し、
    製品経路（MetalBoy アプリ・`MBEmulatorSession`・`metalboy-testrom`）から
    到達できてはならない（MUST NOT）
- **FR-008**: キー割り当て MUST 次の通り固定である。キー割り当ての設定
  変更機能は MUST NOT 存在する
  - ↑↓←→（矢印キー） = 十字キー（D-Pad）
  - Z = B ボタン、X = A ボタン
  - Enter = Start、スペース = Select
- **FR-009**: 音声出力は MUST 存在する。音量の既定値は 50%。音量 0%
  指定時は音を出さずに正常動作する
- **FR-010**: 正常終了時、ウィンドウや音声などの利用リソースを MUST
  適切に解放してプロセスを終了する。異常時に画面・音声の不意な出力が
  持続してはならない
- **FR-011**: 起動に失敗する場合（ROM 未指定・ROM 不在・無効 ROM・
  範囲外オプション等）、原因を説明するエラーメッセージを標準エラー出力に
  出力して MUST 直ちに終了する
- **FR-012**: エミュレーションの対象ハードウェアは DMG（初代 Game Boy）
  に MUST 限定する。CGB 専用機能・CGB 専用 ROM の対応は MUST NOT 存在する
- **FR-013**: セーブ対応カートリッジ（バッテリーバックアップ RAM を持つ
  カートリッジ）のセーブデータは、ROM ファイルと同じ場所に対応する
  セーブファイルとして MUST 保存する。次回起動時にそのセーブファイルが
  存在すれば自動的に復元する。この永続化はゲーム本来のセーブデータであり、
  FR-006 のオプション永続化禁止には含まれない
- **FR-014**: セーブ非対応カートリッジでは、セーブファイルの生成・読み
  込みは MUST 行わない（エラーにもしない）
- **FR-015**: ポーズ（一時停止）機能 MUST NOT 存在する。動作中のランタイム
  操作はキー入力（FR-008）と終了操作のみとする
- **FR-016**: カートリッジマッパーは MBC0（マッパーなし）・MBC1・MBC2・
  MBC3・MBC5 を MUST 対応する。これらを用いる市販 DMG タイトルの大多数が
  動作対象となる。MBC3 の RTC（リアルタイムクロック）は簡易対応とする
  （実時間に基づく挙動の厳密性は計画フェーズで確定する）。範囲外の
  マッパーは FR-011 に従い非対応のエラーで失敗する

### Key Entities *(include if feature involves data)*

- **起動オプション**: 表示倍率（画面スケール x1〜x8、既定 x3）と音量
  （0〜100%、既定 50%）の 2 項目。永続化は行われず、1 回の起動だけに
  有効である
- **ROM ファイル**: Game Boy 用カートリッジイメージ。起動に必須の入力で
  あり、起動時に妥当性が検証される。対応マッパーは MBC0 / MBC1 / MBC2 /
  MBC3 / MBC5 とする
- **キー割り当て**: キーボードのキーと Game Boy ボタン（十字キー / A /
  B / Start / Select）の対応表。固定値であり、変更は不可
- **セーブファイル**: セーブ対応カートリッジのセーブ領域の内容を写した
  ファイル。ROM ファイルと対になって存在し、起動時に読み込み、終了時に
  書き出す。指定があればゲームの進行状態として復元される

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有効な ROM を引数に指定して起動した際、起動コマンド実行から
  ゲーム画面がウィンドウに表示されるまで 2 秒以内である
- **SC-002**: ユーザーのキー操作から画面上の反応まで、体感遅延が 100
  ミリ秒以内である
- **SC-003**: 画面スケール x1〜x8 のすべての値について、指定した倍率に
  応じて表示の大きさが変わることが、各値 5 秒以内の確認操作で検証できる
- **SC-004**: 音量 0% / 50% / 100% の指定において、音の大きさが設定値に
  従って変化することが聴覚で確認できる（0% では完全に無音）
- **SC-005**: 無効な ROM や範囲外のオプションを指定した際、1 秒以内に
  原因を説明するエラーメッセージとともに失敗する
- **SC-006**: 初めて使うユーザーが、ヘルプ／エラーメッセージのみを頼りに
  5 分以内にゲームの起動と基本操作（移動・A/B ボタン）を完了できる
- **SC-007**: CPU 命令・タイミング等のハードウェア挙動を検証する公開テスト
  ROM スイートに合格すること。1 回の起動中にテスト ROM の検証が完了し、
  合格率 100% をリリースの基準とする（合格できない検証項目はリリース
  判断の前に解消または明示的な例外合意が必要）

## Assumptions

- 実行環境は GUI が利用可能なデスクトップ PC（macOS / Windows / Linux 等）
  を想定する
- ROM ファイルはユーザー自身が用意するものとし、ROM の入手・配布は本
  ソフトウェアの範囲外とする
- 終了操作は「表示ウィンドウを閉じる」または「Ctrl+C」を想定する
- セーブデータのファイルへの書き出しは終了時を基本とし、ゲーム動作中の
  連続的な自動保存は想定しない。ゲーム内のセーブ（カートリッジ SRAM への
  書き込み）はゲーム本来の挙動に従う
- 画面スケールの描画方式（拡大アルゴリズムやフィルタリング）は本 spec では
  規定しない。指定したスケール値が表示サイズに反映されることのみを要件とする
- 音量は出力の相対的な大きさとして定義し、音響的な詳細は規定しない
- 対応ハードウェアは DMG（初代 Game Boy）に限定する。CGB 専用機能
  （倍速 CPU、VRAM バンク切替、カラーパレット等）と CGB 専用 ROM は
  対応範囲外とする。アドレスバス上の ROM 内 CGB 対応フラグが立っていても
  DMG 互換モードとして動作できる ROM は DMG として動かす（厳密な
  DMG モード下での CGB 検出の拒否挙動は計画フェーズで確定する）
- キー入力は 1 回の起動中に固定であり、ランタイムでの再割り当て・
  設定 UI は想定しない
- ポーズ機能は提供しない。ゲームは起動から終了まで連続して動作する
- エミュレーション正確性の受け入れ判定には、公開されている挙動テスト ROM
  （blargg 系スイート等）を用いる。使用するスイートの具体的な選定と
  判定手順は計画フェーズで確定する

## Dependencies

- 既存の内部機能・外部システムへの依存なし（新規プロジェクトとして
  実装する）
- Game Boy ハードウェアの公式仕様（Pan Docs 等の公開資料）を参照して
  挙動を定義する
- 実行環境には音声出力と画面表示が可能なデスクトップ環境が必要である
